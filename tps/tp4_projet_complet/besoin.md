# Besoin exprimé par la responsable produit

« À chaque version, quelqu'un passe une heure à relire l'historique Git pour écrire le
CHANGELOG. Je voudrais un petit outil qui le génère à partir de l'historique : ce qui est
nouveau, ce qui est corrigé, et surtout ce qui casse la compatibilité, en premier. Les
messages de commit suivent à peu près la convention Conventional Commits. Le résultat doit
pouvoir être collé tel quel dans CHANGELOG.md. »

Le jeu d’exemple est déjà fourni dans `commits.txt` : le TP ne nécessite pas Git.
